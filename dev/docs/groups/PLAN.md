# Groups board — build plan (2026-10-15)

The Dungeons tab becomes **Groups**: one guild group finder for dungeons, raids, quests and PvP. Look and flow =
mockup v6, layout A (https://claude.ai/artifact/2mRPXHb6ZcyKShReidowt9, builder `dev/art/casc/lfg2_mockup`).
Everything Dungeons does today keeps working the same way. Status: **approved 2026-10-15 with the defaults**; steps 1-6 built (rf/groups): core, board, raids, quests, PvP, bridge + leader page; unverified in game.

## What gets built

**Board** (the tab): "I'm up for" + kind chips (Dungeons, Raids, Quests, PvP) + roles; tabs All / Dungeons / Raids /
Quests / PvP with counts; Now and Later with the groups that want you first ("n want you"), blocked ones last.
Cards: art banner + LFG icon ring; 5 slots up to 5 players, role meters above. Click opens the card in place
(one at a time, scroll kept): **seats** up to 10 players (your ghosted portrait in the place that wants you),
**raid frames** above 10, boss portraits in the header (raids), chips (loot, lockout, bosses / zone / mode), one
why-you-fit line, Join as <role> + whisper + share.

**List a group sheet**: kind tabs. Dungeon = today. Raid = raid tiles (several = one group, e.g. Gruul + Mag; saved
and not attuned marked), places per role with steppers (from the size), full clear or picked bosses, loot (Rolls /
Soft reserve n / Loot council), note, pugs in the Group Finder. Quest = picker (your quest log first, guildies have
them, zones, search), several quests in one zone = one group, a quest that already has a group shows Join instead.
PvP = Arena (bracket, skirmish / rated + min rating), Battlegrounds (WSG 10, AB 15, EotS 15, AV 40, premade, flag
carrier), World PvP (raid). Other = attunement, world boss, farming, reputation (free text). Art band from the pick.

**Leader view** for a raid group: hero with meters, roster by role with open places, requests with hints (BiS here,
brings a missing buff from Team comp, blacklist warning, guest / Group Finder / whisper), "Up for raids, fits a
place" with Invite, the Group Finder eye.

**Ping and invite toasts**: as today, sized to the group ("7/10").

**Raids bridge**: a planned raid short of people gets **Fill open places** (··· menu, whoever runs it). It shows on
the board marked with the team; Ask = the raid's existing join request. Joining a group that overlaps your team's
raid night warns first.

## How (by layer)

### Data
- `Data/Dungeons.lua` stays. New `Data/GroupKinds.lua`: the kinds and activities — raids (from `Data/Raids.lua`
  RaidMeta: size, art, icon, bosses from `Data/BossJournal.lua`, attunement quest IDs), PvP modes (arenas 2/3/5,
  battlegrounds with sizes, world PvP), "other" kinds. Wire indices append-only, like the dungeon list.
- New `Data/GroupQuests.lua`, generated by `dev/generators/gen_group_quests.py` from the cMaNGOS TBC DB
  (`dev/art/tbcdb`, quest_template.SuggestedPlayers >= 2, Outland zones first): quest ID, name, zone, size, chain
  step, Alliance/Horde twin (one key for both).

### Core
- `Core/DungeonRuns.lua` grows into the generic runs model (module name kept: share links `run:<id>`, SavedVariables
  `db.runs`, tests and Home keep working). A run gains `k` (kind) + `a` (activity index for that kind), `n` (size),
  `w` (places per role), and per kind: `lo` loot, `bo` bosses, `q` quest IDs, `pm` PvP mode / bracket / rating.
  Dungeon runs keep today's fields, so **1.4.x clients still see dungeon runs**; runs of other kinds go out with no
  `d`, which old clients already reject (ParseRun), so they simply don't show.
- `Slots` / `OpenRoles` take the run's `w` instead of the fixed 1/1/3 (PvP has no tanks). Join, Accept, Decline,
  asks, invites, lead handoff and the Group Finder stay as they are. Accepting the 6th player converts to a raid
  (the helper in `Core/RaidInvite.lua`).
- Profile (DRP) adds what I'm up for (kinds), my group quests (IDs from the log, only those in GroupQuests, like
  today's daily) and raid lockouts. Raid lockouts and attunements are checked locally, like heroic keys today.
- Digest (DRS) keeps its 3800-byte cap: raid rosters ride along while they fit, else counts only, and opening
  such a card asks the owner for the roster.
- New `Core/GroupQuests.lua`: quest log scan (QUEST_LOG_UPDATE, QUEST_TURNED_IN), "a group for this quest exists",
  zone rule, a quest group ends once everyone in it turned the quest in.
- New `Core/GroupPvP.lua`: arena teams and ratings (GetArenaTeam), one group per kind of yours (a new arena group
  replaces the old one; a battleground group ends your arena group), rated = team members only (+ team invite).
- Raids starting: the leader is offered the raid session with the listed loot method (GroupRules features: rolls /
  reserves with n each / council, guild members only for council).
- `Core/RaidPlan.lua`: raid field `fo` (fill open places) + the board entry built from the raid's own roster
  (GetRaidOpenSlots) — no new message.

### UI
- `UI/DungeonsTab.lua` (2106 lines, near the 200-locals limit) is split: `UI/GroupsBoard.lua` (board, cards, opened
  card), `UI/GroupsSheet.lua` (list sheet, all kinds), `UI/GroupsLead.lua` (leader view), `UI/GroupsToast.lua`
  (ping + invite). Shared helpers stay in `UI/Widgets.lua` / EUI (ring, pills, chips, art crop).
- MainFrame: tab label "Groups", key `dungeons` kept (saved tab, share links). NavMenu / Home calendar / Notify /
  Share / welcome tour updated to the new name and kinds.
- Art: all client textures by file ID (loading screens, LFG icons cut to the picture — texcoords 6/64..45/64 x
  4/64..43/64, EJ boss pictures, arena / battleground screens, marks); no new media files expected. If a glyph is
  missing it goes in `gen_strategy_media.py` and the art pack is raised.

## Testing
- Harness tests in `dev/tests/groups/`: wire compat (1.4.x client + new client on one guild), slots for every size,
  raid conversion, quest dedupe / zone rule / end on turn-in, one group per kind, rated team rule, digest cap with 25-man
  rosters, Fill open places, overlap warning. Today's `tests/dungeons` keep passing unchanged.
- `ui_audit` views for every board state, opened card (5 / 10 / 25 / 40), sheet kind, leader view, toasts; rendered
  with `--look` and checked before reporting.
- Demo mode covers every flow (made-up groups, nothing sent).

## Order (each step usable on its own)
1. Core model + wire compat + tests (no UI change yet).
2. Board: tabs, sizes, sorting, opened card. Dungeons look like the mockup from here on.
3. Raids: sheet rows, leader view, raid conversion, loot method → session, lockouts, attunement.
4. Quests: generator + data, log scan, picker, dedupe.
5. PvP: modes, arena teams, one-group-per-kind.
6. Raids bridge, overlap warning, toasts, Home / Notify / Share / tour, demo, changelog; full release.

## Unverified until in game
Arena API returns on this client; the Group Finder's activity IDs for raids and battlegrounds; quest log events order;
digest sizes with several 25-man groups; raid conversion timing on accept.
