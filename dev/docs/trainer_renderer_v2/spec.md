# Raid Trainer room renderer v2: final implementation spec

Status: design final, nothing implemented. Base: Design 3 (exact-copy BSP painter, robustness first). The fatal flaws the judges found are fixed:

- Horizontal-depth cut planes. Replaced by a per-actor half-space rule that holds at every pitch.
- Nested SetClipsChildren copy frames. Replaced by clipping in Lua.
- Whole-leaf gcut. Replaced by box-minus-box restriction.
- UnderActor skip, which broke closure. Removed.

Grafted ideas:

- Cluster frames, so no texture ever gets SetParent (D1).
- The exact max-affine-error bound, the τ controller and the self-check probe (D1).
- Edge-keyed midpoints and a per-edge UV morph (D2), with the affine weights corrected (two designs had them swapped; see §A.2).
- 5-ray camera collision and a pivot-height spring (D1).
- render_bench (D1).

Everything here was reasoned and measured offline; nothing has been seen in the game client.

## 0. What changes and why it fixes each symptom

| User symptom | Root cause (audit / render_check) | Fix in v2 |
|---|---|---|
| Background drawn over foreground | UpdateOcclusion lifts single triangles above the ModelScene and breaks BSP order (D1/D6). The baseline Vashj actor walk is 33.9% wrong. | **No lift.** The room is always drawn complete, in exact BSP order, under the single ModelScene, on fixed frames with unique positions (§4, §5.4). Characters are hidden by **copies**: the room pieces on the camera side of the actor's plane, clipped in Lua to the actor's screen box and drawn above the scene. A copy set is a per-ray prefix, so it can never change a room pixel (proof §5.13.6). |
| Triangles disappear, holes at the bottom, seeing through | NEAR = 2 yd plus dropped crossing pieces (D3). The camera goes inside walls (no collision). Possible alpha see-through (D7). | Exact near clip at 0.5 yd, the same as SetCameraNearClip; crossing pieces are never dropped (§5.8). Camera collision with the room and a spring on the eye height (§5.2). Textures anchored at the scene CENTER (§4.3). SetBlendMode("DISABLE") for opaque WMO materials (§2). Vertex positions written with 3 decimals, so BSP T-junction gaps fall below 0.2 px. |
| Stretching | The subdivision rule caps the depth ratio, not the screen error (D2). | Pieces are split until the **exact maximum affine error** on every edge is at most τ screen pixels (§5.7). τ is 1.5–5 px, adaptive. |
| Swimming / popping / flicker while moving | The level switches at a hard threshold every frame (D4). Seams (D5). Lift flicker (D6). Pixel snapping (research Q3). | Cuts follow world-space longest-edge bisection, so they are camera-independent. Hysteresis. A per-edge UV morph, so a split or merge is invisible. Snapping turned off. Order changes only through SetFrameLevel and SetDrawLayer on fixed frames. |
| Frame rate | About 10k widget calls per moving frame, 13–25 ms of mock Lua. | AABB frustum culling, lazy projection, generator quads, persistent keyed textures with cached setters, and a time- and count-based τ controller. A still camera makes 0 room calls (§5.14, §11). |

Kept: the generator's BSP tree and its traversal rule. Calibrate (pitchSign and mirror). The 3-probe basis measurement. The single ModelScene, its actors, plates, labels, minimap and HUD. The flat floor-map fallback.

Not done (non-goals): occlusion culling (D2's coverage bands), several ModelScenes or actor layers, sibling quads by default, per-vertex light gradients, and geometry LOD.

## 2. Generator changes and the exact data format v2

Edit `DEV/generators/gen_trainer_heights.py`. The BSP build (`build_bsp`, seed 7), the room transforms, `max_edge` (Teron 9, Vashj 40) and the height rows stay unchanged, so node layout and node count stay the same: Teron 1338 nodes, Vashj 1511.

1. **Precision.** Write x, y, z with 3 decimals (a new `num3`), u, v with 4 decimals (`num4`), and light with 2 (`num`). The vertex dedupe key in `vert()` becomes `(round(x,3), round(y,3), round(z,3), round(u,4), round(v,4), round(light,2))`.
2. **Textures keyed by (fileID, blend).** In `build_mesh`, `tex_index` is keyed by `(file_id, blend)`, where `blend = root["materials"][mat]["blend"]` (wmo_tools already reads MOMT blend). Emit `textures` (file IDs, which may repeat) and a parallel `blend` list of strings: MOMT 0 → `"DISABLE"`, 1 → `"ALPHAKEY"`, anything else → `"BLEND"`. Both rooms are known to be all blend 0.
3. **Quad pairs: `pair`.** One number per triangle, the 1-based index of its quad mate or 0. Pairing is greedy, node by node, in triangle order. For triangle i, try its edges longest first, and pair with an unpaired j only when all of the following hold:
   - same node (so coplanar) and same texture index;
   - they share exactly one edge by vertex index (p, q), and i walks p→q while j walks q→p (consistent winding);
   - the normals agree (dot > 0);
   - for the quad (a, b, d, c), where i = (a, b, c) is rotated so that the shared edge is (b, c) and d is j's lone vertex, the union is strictly convex: segments a–d and b–c cross properly, with a 1e-4 margin in the plane;
   - UV consistency: d's UV equals the affine map of triangle i (3D position → UV) evaluated at d's position, within 1e-3 (needs the 4-decimal UVs);
   - the light span over the 4 corners is at most 0.15.

   Expected: about 45% of Teron's triangles and 55% of Vashj's are paired (D3 measured 2186 of 4757 and 3660 of 6455 with a looser tolerance).
4. **`version = 2`.**
5. **Self-checks** (the run fails on any of them):
   - every triangle lies within 0.03 yd of its node's plane;
   - every pair passes the rules above when re-checked;
   - node count ≤ 3000;
   - no vertex index out of range.

   Print triangles, vertices, nodes, pairs, distinct textures and file KB.
6. Delete the unused `BAND` constant. Update the header comment so it documents `blend`, `pair` and `version`.

Format (fields kept: w, h, base, step, alphabet, rows, mesh.textures, verts, tris, nodes):

```lua
ns.TrainerFloors.<key> = { w = , h = , base = , step = , alphabet = "", rows = { ... }, mesh = {
  version = 2,
  textures = { fileID, ... },             -- per texture index (1-based), a file may repeat with another blend
  blend    = { "DISABLE", ... },          -- per texture index: "DISABLE" | "ALPHAKEY" | "BLEND"
  verts = { x, y, z, u, v, light, ... },  -- arena yards (x east, y north, z up); x,y,z 3 decimals; u,v 4 decimals
  tris  = { a, b, c, tex, ... },          -- 1-based vertices; listed node by node (contiguous per node)
  nodes = { A, B, C, D, front, back, firstTri, triCount, ... },  -- plane (unit normal 4 decimals, D 2 decimals);
                                          -- front = child on the positive side (A*x+B*y+C*z+D > 0); 0 = none; root = node 1
  pair  = { mate or 0, ... },             -- per triangle
} }
```

At run time, `version ~= 2` is treated as all pairs 0 and blend "DISABLE".

Run: `luaenv/Scripts/python.exe generators/gen_trainer_heights.py` (both rooms).

## 3. Run-time data structures (Room.lua)

All hot data lives in flat parallel arrays, which are file-level locals. Nothing is allocated per frame: scratch tables are reused, and the camera key is compared numerically.

**Lua 5.1 limits:**

- A function may reference at most **60 upvalues**. Keep every hot function under 50; if needed, read rarely used values from a table.
- A function may have at most 200 locals.
- There is no integer division (use `math.floor`) and no `goto`.

**Constants** (top of Room.lua; the tunable ones are mirrored in `Room.opts`):

```
NEAR = 0.5            -- = SetCameraNearClip (UI passes the same value); render_check's truth clips here too
MARGIN = 2            -- px frustum margin
TAU_START, TAU_MIN, TAU_MAX, MERGE = 2.0, 1.5, 5.0, 0.75
TARGET_START, TARGET_MIN, TARGET_MAX, HARD_CAP = 1600, 900, 2200, 2800    -- room leaves (textures) per frame
TARGET_MS = 4.0       -- renderer ms per camera-driven redraw (debugprofilestop), in game only
MAXDEPTH = 18         -- bisection levels; MINCLIP = 0.05 yd (crossing pieces are split down to this, then clipped)
DIL = 0               -- corner dilation px (fallback 0.35, see §5.9.4)
CAP_NODES = 32        -- nodes per room cluster frame (64 positions); ROOM_FRAMES_MAX = 200
EPS_SIDE = 1e-4       -- |side| below this: the node is seen edge-on, skip its prims
LINE_EPS = 0.02       -- plane classification of mark segments
OCC_SLOTS = 16        -- occluders that get copies; 2 copy frames each (128 positions)
COPY_TEX_MAX = 600    -- copy textures per frame (all actors)
G_MIN = 0.5           -- yd: horizontal camera-actor distance below which the actor uses the depth rule (family B)
KP = 4194304          -- 2^22: piece key = prim*KP + path*4 + kind (kind 0 leaf, 1 second near-clip texture, 2 sibling quad)
MIDK = 262144         -- 2^18: midpoint cache key = lo*MIDK + hi (point ids < 2^18); TMP0 = MIDK + 16 (temporary points)
```

**Mesh (built once by `Prepare`, about 15–25 ms):**

- Points (base vertices are ids 1..nV, midpoints nV+1.., temporaries TMP0+1..):
  - World data (fixed): `WX, WY, WZ` (arena coordinates) and `TU, TV` (true UV). `MA, MB` hold a midpoint's parent edge endpoints (nil for base vertices).
  - Per-frame data, valid while `PS[id] == gen`: `PR, PU, PD` (camera space: right, up, depth), `PX, PY, PQ` (screen position from the scene's BOTTOMLEFT, and √depth; valid only when PD > NEAR), `DU, DV` (display UV: TU/TV for base vertices; morphed for midpoints, §5.6).
- Nodes: `NA, NB, NC, ND` (plane), `NFR, NBK` (children), `FP, LP` (first and last prim), subtree AABB `SX0, SY0, SZ0, SX1, SY1, SZ1`, own-prim AABB `OX0..OZ1`, `frameOf[k]`, and the per-frame values `side[k]`, `sideSign[k]` (true when side > 0), `rankOf[k]`, `orderNode[r]`, `pos[k]` (0..63 inside its frame), plus `fOrd[f]`.
- Prims (stored node by node, contiguous): `QA, QB, QC, QD` (QD = 0 for a triangle; a quad is cyclic (a, b, d, c) in i's winding, so its LL–UR diagonal is the original shared edge), `QTEX`, `QL` (mean corner light), `QO` (+1 if the prim's winding normal agrees with its node's plane normal, −1 if opposite, 0 if degenerate), `QN` (node), `QPOOL` (pool key = fileID*4 + blendCode).
- Clusters: `nFrames`, and per frame the node count. Algorithm:
  1. `size[k]` is computed post-order.
  2. Visit nodes in pre-order. A node k with no frame yet and `size[k] ≤ CAP_NODES` gets a new frame holding its whole subtree, with `froot[f] = k`.
  3. Every other node is a "top node". If one of its children c has `froot[frameOf[c]] == c`, that frame has fewer than CAP_NODES nodes and has not yet absorbed a top node, the top node joins that frame (choose the smaller child frame). Otherwise it gets a frame of its own.
  4. A frame's nodes are always contiguous in the traversal: a full subtree, or a full subtree plus its parent.
  5. Guard: `nFrames ≤ ROOM_FRAMES_MAX`. Otherwise print once, `"Raid Trainer: this room has too many parts for the 3D renderer"`, and use the flat fallback.
- Floor grid: triangles with nz ≥ 0.7·|n|, in 8 yd cells (today's `mesh.grid` logic), for `FloorZ`.
- Collision: the BSP itself (no extra grid).

**Pieces and pools:**

- `live[key]` → texture, plus `liveList`/`nLive`.
- `freeLists[frame][pool]` holds the free textures of that frame and file+blend. Textures never change frame.
- Fields on each texture (WoW widgets are Lua tables): `key`, `gen`, `frame`, `pool`, `light`, `pos`, `shown`, `uvOk`, `u1,v1,…,u4,v4` (the texcoords as sent, in UL, LL, UR, LR order).
- Hysteresis: two tables, `splitPrev` and `splitCur`, swapped at each redraw (the old one is wiped then).
- Midpoint cache `midOf[key]` → id, with `nPts`. When nPts reaches MIDK − 16, set `wipeMid`; at the next redraw start, clear `midOf` and the midpoint entries and reset nPts = nV. Texture keys are path-based, so wiping midpoints never invalidates a texture.
- Leaf records (one per emitted room texture this redraw, for copies): `nRec`, `RTX` (texture), `RN` (node), `RP` (prim), `RK` (3 or 4 corners), `R1..R4` (corner point ids).

**Lines:**

- Pools per room frame, plus the bottom line frame and the copy frames. Fields on each Line: `pos`, `thick`, `r,g,b,a`, `x1,y1,x2,y2`, `shown`.
- Placed-segment records: arena endpoints, screen endpoints, key (2·rank+1, or −1 for the bottom frame), colour and thickness.

**Occluders:**

- Records with: `id`, family (`"A"`, `"B"` or `"skip"`), axis point A, normal n, φ coefficients (a, b, e, k), box `bx0, by0, bx1, by1`, `dMin`, slot, priority.
- The actor-id → slot map is kept from frame to frame (stable).

## 4. Frames, levels, anchoring, snapping, blend

### 4.1 Frame stack

Levels are relative to `V = view:GetFrameLevel()`. All frames are children of `view`, which keeps `SetClipsChildren(true)` (unchanged, and confirmed to work in game).

| Offset | Frame |
|---|---|
| +1 | floorFrame (flat fallback; unchanged) |
| +2 | Room bottom line frame (mark segments ranked before every node) |
| +3 … +3+nFrames−1 (≤ +202) | room cluster frames; frame f is at level `V + 3 + fOrd[f] − 1` |
| **+210** | ModelScene (was +70) |
| +211 … +242 | copy frames: occluder slot j (0..15) uses `V+211+2j` and `V+212+2j` |
| +250 | plateFrame (was +140) |
| +252 | arena (minimap) and `hud.frame` (was +142) |
| +253 | `R.timer`, hud FontString frame (was +143) |
| +268 | focusOverlay (was +158) |
| +270 | overlay (was +160) |

Rules:

- Define these as one table in UI.lua (`LV = { floor=1, lines=2, room0=3, scene=210, copy0=211, plates=250, arena=252, hud=253, focus=268, overlay=270 }`) and pass it to `Room.Attach`.
- Every room and copy frame uses `SetAllPoints(view)`.
- Room.lua reads `V` every frame. If V changed (the parent was re-levelled), it re-applies every room, copy, line and scene level (the room frames through pass 1b). HUD frames shift with their parent and need nothing.
- Guard at CreatePanel: if `V + 270 > 9990`, print once. Never make the root toplevel.

### 4.2 Draw positions inside a frame

A frame has 64 positions, `p = 0..63`, mapped to `layer = LAYERS[floor(p/16)+1]` with `LAYERS = {"BACKGROUND","BORDER","ARTWORK","OVERLAY"}`, and `sublevel = p % 16 − 8`. HIGHLIGHT is never used.

- Room node k uses position `pos[k] = 2·(local rank)`.
- Mark lines lying right after node k use `pos[k] + 1` (odd).
- Copy frames use the same 64-position mapping.

No two frames ever share a level, and only textures of one node share a position. Those are coplanar, non-overlapping triangles (verified by the audit) and pieces of them. Lines share a position only with lines.

### 4.3 Texture setup (once per texture, at creation)

```lua
tx = frame:CreateTexture(nil, "BACKGROUND")
tx:SetSize(1, 1)
tx:SetPoint("CENTER", scene, "CENTER", 0, 0)      -- the 1x1 base rect sits mid-view: any cull/clip test on it passes
if tx.SetSnapToPixelGrid then tx:SetSnapToPixelGrid(false) end
if tx.SetTexelSnappingBias then tx:SetTexelSnappingBias(0) end
tx:SetTexture(fileID, "REPEAT", "REPEAT")
tx:SetBlendMode(blend)                             -- "DISABLE" for opaque materials (Room.opts.opaque=false -> "BLEND")
tx.shown = true                                    -- new regions are shown
```

Lines (`frame:CreateLine(nil, "BACKGROUND")`) get the same two snapping calls. The fallback floor tiles in `DrawFloorMap` also get them.

Vertex offsets, with `ox, oy = W/2, H/2` (the scene centre measured from its BOTTOMLEFT) and target corners `(x, y)` in scene units from BOTTOMLEFT:

```lua
local VUL, VLL, VUR, VLR = UPPER_LEFT_VERTEX or 1, LOWER_LEFT_VERTEX or 2, UPPER_RIGHT_VERTEX or 3, LOWER_RIGHT_VERTEX or 4
tx:SetVertexOffset(VUL, xUL - ox + 0.5, yUL - oy - 0.5)
tx:SetVertexOffset(VLL, xLL - ox + 0.5, yLL - oy + 0.5)
tx:SetVertexOffset(VUR, xUR - ox - 0.5, yUR - oy - 0.5)
tx:SetVertexOffset(VLR, xLR - ox - 0.5, yLR - oy + 0.5)
tx:SetTexCoord(uUL, vUL, uLL, vLL, uUR, vUR, uLR, vLR)        -- 8-argument form
```

Corner mapping. The source winding is always kept and corners are never reordered.

- **Triangle (P1, P2, P3):** UL = P1, LL = P2, UR = P3, LR = P3 (same position and same texcoord).
- **Quad, cyclic (P1, P2, P3, P4):** UL = P1, LL = P2, LR = P3, UR = P4. The client is believed to split along LL–UR (P2–P4); see §13 for why nothing depends on that guess except sibling quads.

## 5. Per-frame algorithm

### 5.1 Order in UI.lua `Draw3D(elapsed)`

```lua
local function Draw3D(elapsed)
    local mesh = sim.enc.arena.mesh
    local room = Room and mesh and Room.SetMesh(mesh)          -- no-op when unchanged; false = flat fallback
    if not cam.calibrated then Calibrate() end
    PlaceCamera(elapsed, room)                                  -- §5.2 (spring, collision, scene camera)
    DrawActors()
    DrawFxActors()                                              -- moved before the room: occluder boxes need fx

        if Room.BeginFrame(cam) then                            -- §5.3
            Room.SetOccluders(BuildOccluders())                 -- §5.13.1
            Room.DrawRoom()                                     -- §5.4–5.11 (returns at once when the key is unchanged)
            Room.BeginLines() DrawEffects() Room.EndLines()     -- §5.12 (DrawEffects calls Room.Line in mesh mode)
            Room.DrawCopies()                                   -- §5.13

```

`Draw()` takes `elapsed` from `OnUpdate`. Calls without it (`ShowResult`) pass nil, which means snap. Also call `Room.Clear()` from `ResetScene`.

### 5.2 Camera (UI.lua `PlaceCamera(dt, room)` and `Room.CameraDistance`)

- `cam.dist` stays the wanted distance (mouse wheel, 5..35) and `cam.pitch` the mouse-look pitch (0.05..1.3).
- New fields: `cam.cur` (the distance actually used), `cam.hz` and `cam.hv` (pivot height spring), and `cam.px`, `cam.py`, `cam.lastDist`, `cam.lastPitch`.
- If `Room.opts.camDt` is a number, it replaces `dt` (render_check walks). A nil dt means snap.

**Snap** when any of these holds: `dt == nil`; `cam.hz == nil`; the player moved more than 3 yd since the last frame; `|dist − lastDist| > 0.15`; `|pitch − lastPitch| > 0.15`; or `|target height − hz| > 2`.

Pivot height: `target = GroundZ(p.x, p.y) + 2.2`. When not snapping, use a critically damped implicit spring with ω = 12/s:

```lua
local function Spring(x, v, target, w, dt)
    local f, hw2 = 1 + 2 * dt * w, dt * w * w
    local det = 1 / (f + dt * hw2)
    return (f * x + dt * v + dt * hw2 * target) * det, (v + hw2 * (target - x)) * det
end
```

Collision (only when `room` and `Room.opts.collision`):

- `allowed = Room.CameraDistance(p.x, p.y, cam.hz, cam, cam.dist)`.
- `cam.cur = allowed` if snapping or `allowed < cam.cur`; otherwise `cam.cur = min(allowed, cam.cur + 6*dt)`.
- Camera position: `pivot − F·cam.cur`, with pivot `(p.x, SY(p.y), cam.hz)` in scene coordinates.

`Room.CameraDistance` works in arena coordinates and uses 5 rays. Each starts at the pivot P0 (not offset, so hugging a wall does not zoom the camera in) and ends at `P0 − F·want + o`, with `o ∈ {0, ±0.35·R ± 0.25·U}`. R, U and F are the arena camera vectors (§5.3). Let `tmin` be the smallest hit parameter in (0, 1]. Then `allowed = tmin and max(0.8, tmin·want − 0.6) or want`. The result is cached: no rays when the pivot, yaw, pitch and dist are unchanged.

BSP segment cast (front to back, both faces count):

```lua
local function Cast(k, P0, P1, t0, t1)                -- S(t) = P0 + t*(P1-P0); returns first hit t or nil
    if k == 0 then return nil end
    local s0, s1 = Plane(k, S(t0)), Plane(k, S(t1))
    local c0 = s0 > 0.02 and 1 or (s0 < -0.02 and -1 or 0)
    local c1 = s1 > 0.02 and 1 or (s1 < -0.02 and -1 or 0)
    if c0 * c1 >= 0 then                               -- no proper crossing
        if c0 + c1 > 0 then return Cast(NFR[k], ...t0, t1)
        elseif c0 + c1 < 0 then return Cast(NBK[k], ...t0, t1)
        else return Cast(NFR[k], ...) or Cast(NBK[k], ...) end   -- lies in the plane
    end
    local near, far = (c0 > 0) and NFR[k] or NBK[k], (c0 > 0) and NBK[k] or NFR[k]
    local tm = t0 + (t1 - t0) * s0 / (s0 - s1)
    local h = Cast(near, P0, P1, t0, tm); if h then return h end
    if HitNodeTris(k, S(tm)) then return tm end         -- barycentric in each node triangle, 0.05 yd tolerance
    return Cast(far, P0, P1, tm, t1)
end
```

### 5.3 `Room.BeginFrame(cam)`

1. Read `W, H = scene:GetWidth(), scene:GetHeight()` and `es = scene:GetEffectiveScale()`. Return false if W, H ≤ 0. Read `V`, re-level if it changed (§4.1).
2. **Camera key.** Compare `cam.x, cam.y, cam.z, cam.fx, cam.fy, cam.fz, W, H, es` numerically with the last values. If all are equal and nothing is invalidated, set `camMoved = false` and return true.
3. **Probes** (unchanged from today's DrawMesh, lines 568–580): with `rx, ry = fy/flat, −fx/flat` and `ux, uy, uz = ry·fz, −rx·fz, rx·fy − ry·fx` in scene coordinates, probe 10 yd ahead, then 1 yd right, then 1 yd up. Divide by `es` to get `cx, cy, exx, exy, eyx, eyy`, where `exx = (px1/es − cx)·10` and so on. If any probe returns nothing, set `camMoved = false` and return true; the last picture stays.
4. **Arena camera** with `m = cam.mirror`: `E = (cam.x, m·cam.y, cam.z)`, `F = (fx, m·fy, fz)`, `R = (rx, m·ry, 0)`, `U = (ux, m·uy, uz)`. For an arena point P with `D = P − E`: `d = D·F`, `r = D·R`, `u = D·U`. Screen position: `x = cx + (r·exx + u·eyx)/d`, `y = cy + (r·exy + u·eyy)/d`.
5. **Frustum**, as camera-space coefficient triples `(ar, au, ad)`. A point is inside when `ar·r + au·u + ad·d ≥ 0`:
   - left: `(exx, eyx, cx + MARGIN)`
   - right: `(−exx, −eyx, W + MARGIN − cx)`
   - bottom: `(exy, eyy, cy + MARGIN)`
   - top: `(−exy, −eyy, H + MARGIN − cy)`
   - near: `d − NEAR ≥ 0`

   For AABB tests, the arena normal is `n = ar·R + au·U + ad·F`, with the planes through E (the near plane offset by NEAR). These hold for points behind the camera and for any screen mapping.
6. **Self-check** on every 30th camera move:
   - Project `E + 25F + 4R + 2U` with the Lua basis and with `Project3DPointTo2D` (divided by es).
   - Store `stats.selfCheckPx`.
   - After 10 consecutive checks above 1.5 px, print once: `"Raid Trainer: the room may not line up with the characters (projection check off by N px). Please report this."`

### 5.6 Point preparation (`Prep(id)`): lazy projection and display UV

```lua
local function Prep(id)
    if PS[id] == gen then return end
    PS[id] = gen
    local dx, dy, dz = WX[id] - ex, WY[id] - ey, WZ[id] - ez
    local d = dx * Fx + dy * Fy + dz * Fz
    local r, u = dx * Rx + dy * Ry + dz * Rz, dx * Ux + dy * Uy + dz * Uz
    PR[id], PU[id], PD[id] = r, u, d
    if d > NEAR then
        PX[id], PY[id], PQ[id] = cx + (r * exx + u * eyx) / d, cy + (r * exy + u * eyy) / d, sqrt(d)
    end
    local a = MA[id]
    if a then                                      -- midpoint of edge (a, b): both already prepared (parent corners)
        local b = MB[id]
        local mu, mv = (DU[a] + DU[b]) * 0.5, (DV[a] + DV[b]) * 0.5    -- the "exact" texel along the 3D edge
        local da, db = PD[a], PD[b]
        if morphOn and da > NEAR and db > NEAR then
            local lx, ly = PX[a] - PX[b], PY[a] - PY[b]
            local e = sqrt(lx * lx + ly * ly) * abs(da - db) / (2 * (da + db))   -- px offset of the true midpoint
            local t = (e - tau) / tau                                         -- 0 at e = tau, 1 at e = 2 tau
            if t < 1 then
                if t < 0 then t = 0 end
                local s = da + db                                           -- what the UNSPLIT parent showed there:
                local au, av = (da * DU[a] + db * DU[b]) / s, (da * DV[a] + db * DV[b]) / s   -- see §A.2 (weights!)
                mu, mv = au + (mu - au) * t, av + (mv - av) * t
            end
        end
        DU[id], DV[id] = mu, mv
    end
end
```

- For base vertices, DU and DV are set once in Prepare (= TU, TV).
- The morph is a pure function of the edge, so both triangles that share a split edge use the same UV at its midpoint: no seam along shared split edges.
- At the moment of a split (max edge error = τ, so this edge's midpoint error is ≤ τ and t = 0), and at a merge (error below 0.75τ, t = 0), the children reproduce the parent exactly, so neither can be seen.

`Mid(a, b)`:

```lua
local function Mid(a, b)
    if a > b then a, b = b, a end
    local key = a * MIDK + b
    local id = midOf[key]
    if id then return id end
    if nPts >= MIDK - 16 then wipeMid = true; id = NewTemp() else nPts = nPts + 1; id = nPts; midOf[key] = id end
    WX[id], WY[id], WZ[id] = (WX[a] + WX[b]) * 0.5, (WY[a] + WY[b]) * 0.5, (WZ[a] + WZ[b]) * 0.5
    TU[id], TV[id] = (TU[a] + TU[b]) * 0.5, (TV[a] + TV[b]) * 0.5
    MA[id], MB[id] = a, b
    return id
end
```

### 5.7 Subdivision: error bound, hysteresis, budget

**Error bound** (exact; derivation in §A.1). An edge with endpoint depths d1, d2 > NEAR and screen length L has a largest affine-mapping displacement of

`e = L·|√d1 − √d2| / (√d1 + √d2)`.

A piece is drawn whole only if every edge satisfies e ≤ τ. That covers 3 edges for a triangle, and 4 edges plus both diagonals for a quad, so the result holds whichever diagonal the GPU uses. The test is done squared, with no sqrt:

```lua
local function Over(a, b, t2)
    local dx, dy = PX[a] - PX[b], PY[a] - PY[b]
    local ds, ss = PQ[a] - PQ[b], PQ[a] + PQ[b]
    return (dx * dx + dy * dy) * ds * ds > t2 * ss * ss
end
```

Here `tau2 = τ²` and `merge2 = (0.75τ)²`. **Hysteresis:** a key that was split in the previous redraw (`splitPrev[key]`) stays split until its error drops below 0.75τ.

```lua
RefineTri = function(p, path, a, b, c, lev)
    Prep(a); Prep(b); Prep(c)
    if Out3(a, b, c) then return end                  -- all 3 outside one frustum plane (camera space; valid behind)
    local key = p * KP + path * 4
    local crossing = PD[a] < NEAR or PD[b] < NEAR or PD[c] < NEAR
    local split = false
    if crossing then
        split = lev < MAXDEPTH and max(W2(a, b), W2(b, c), W2(c, a)) > MINCLIP * MINCLIP
    elseif lev < MAXDEPTH and nLeaves < hardCap then
        local t2 = splitPrev[key] and merge2 or tau2
        split = Over(a, b, t2) or Over(b, c, t2) or Over(c, a, t2)
    end
    if split then
        splitCur[key] = true
        local lab, lbc, lca = W2(a, b), W2(b, c), W2(c, a)  -- WORLD lengths: bit-identical every frame
        local P, Q, R
        if lab >= lbc and lab >= lca then P, Q, R = a, b, c
        elseif lbc >= lca then P, Q, R = b, c, a
        else P, Q, R = c, a, b end
        local M = Mid(P, Q)
        RefineTri(p, path * 2, P, M, R, lev + 1)          -- (P, M, R) and (M, Q, R) keep the winding
        RefineTri(p, path * 2 + 1, M, Q, R, lev + 1)
    elseif crossing then EmitClip(p, key, 3, a, b, c, nil)
    else Emit(p, key, 3, a, b, c, c, false) end
end

RefineQuad = function(p, path, a, b, c, d, lev)        -- cyclic a, b, c, d
    Prep(a); Prep(b); Prep(c); Prep(d)
    if Out4(a, b, c, d) then return end
    local key = p * KP + path * 4
    local crossing = PD[a] < NEAR or PD[b] < NEAR or PD[c] < NEAR or PD[d] < NEAR
    local split = false
    if crossing then
        split = lev < MAXDEPTH and max(W2(a, b), W2(b, c), W2(c, d), W2(d, a)) > MINCLIP * MINCLIP
    elseif lev < MAXDEPTH and nLeaves < hardCap then
        local t2 = splitPrev[key] and merge2 or tau2
        split = Over(a, b, t2) or Over(b, c, t2) or Over(c, d, t2) or Over(d, a, t2) or Over(a, c, t2) or Over(b, d, t2)
    end
    if split then
        splitCur[key] = true
        if W2(a, b) + W2(c, d) >= W2(b, c) + W2(d, a) then
            local m1, m2 = Mid(a, b), Mid(c, d)
            RefineQuad(p, path * 2, a, m1, m2, d, lev + 1)
            RefineQuad(p, path * 2 + 1, m1, b, c, m2, lev + 1)
        else
            local m1, m2 = Mid(b, c), Mid(d, a)
            RefineQuad(p, path * 2, a, b, m1, m2, lev + 1)
            RefineQuad(p, path * 2 + 1, m2, m1, c, d, lev + 1)
        end
    elseif crossing then EmitClip(p, key, 4, a, b, c, d)
    else Emit(p, key, 4, a, b, c, d, false) end
end
```

`W2` is the squared world-space length. **Hard cap:** once `nLeaves ≥ hardCap`, pieces in front of the near plane stop splitting and are drawn at their current level. Their error can exceed τ, but nothing is ever dropped.

**Sibling quads** (`opts.siblingQuads`, default **false**): when both children of a triangle split are whole leaves, they are emitted as one texture with key `p*KP + path*4 + 2`, cyclic `(P, M, Q, R)`, so its LL–UR diagonal is M–R. This depends on the LL–UR guess (§13) and saves about 25% of the textures.

### 5.8 Near-plane clipping (never drop)

Pieces that cross the near plane are always split until the longest world edge is under MINCLIP (0.05 yd) or the depth reaches MAXDEPTH. Each resulting piece is then clipped exactly in camera space:

- Sutherland–Hodgman against `d ≥ NEAR`.
- New points are temporaries (`NewTemp()`: ids TMP0 + nTmp, reset per redraw). Their WX, WY, WZ, PR, PU, PD, DU and DV are interpolated linearly in 3D at `t = (NEAR − d_i)/(d_j − d_i)`; then PX, PY and PQ are projected and PS is set to gen.
- A triangle gives 3–4 corners, which become one texture.
- A quad gives 3–5 corners. Four or fewer become one texture. Five become two: the quad `(v1,v2,v3,v4)` with key `key`, and the triangle `(v1,v4,v5)` with key `key+1`.
- Clipped leaves always re-send their texcoords.
- Pieces entirely behind the near plane or outside the frustum are culled by `Out3`/`Out4`.

With camera collision, near-clipped leaves happen only when geometry touches the camera.

#### 5.9.2 `UVMoved`

Returns true when any corner's display UV differs from the cached one by more than 0.3 px worth of texture. Use `kpx = (screen length of the leaf's longest screen edge) / (its UV length)`, and resend when `max |Δuv| · kpx > 0.3`. If the UV length is below 1e-6, resend on any change above 1e-6. Leaves whose corners are all base vertices never resend.

#### 5.9.3 Keys

`key = prim·2^22 + path·4 + kind`. path is the bisection heap index (root 1, children 2p and 2p+1, depth ≤ 18). kind is 0 for a leaf, 1 for the second near-clip texture and 2 for a sibling quad. Keys stay below 3·10^10, well within exact double range. A key always maps to the same frame, because the prim belongs to one node.

#### 5.9.4 `Corners`

Returns the target corners in UL, LL, UR, LR order from PX and PY.

- With DIL = 0 (the default), these are the exact projections.
- With DIL > 0 (the fallback), every corner is pushed DIL px outward from the leaf's screen centroid: `p += DIL·(p − g)/|p − g|`.
- The copy pass calls the same function, so the copies get the same corners.
- Enabling DIL is the trigger-based step in §12: do it only if render_check reports holesPct > 0.01 in any pose.

### 5.11 Budget controller (only after a redraw caused by camera motion)

Count-based, always on unless `opts.tau` fixes τ:

- If `nLeaves > 0.95·hardCap`: `τ = min(TAU_MAX, τ·1.25)`.
- Else if `nLeaves > 1.1·target`: `τ = min(TAU_MAX, τ·1.08)`.
- Else if `nLeaves < 0.8·target`: `τ = max(TAU_MIN, τ·0.97)`.

Time-based, only when `opts.adaptiveTime` is set and `debugprofilestop` exists (render_check and tests turn it off):

- `ms` = debugprofilestop() around DrawRoom, lines and DrawCopies.
- After 3 consecutive redraws over TARGET_MS: `target = max(TARGET_MIN, target·0.9)`.
- After 60 consecutive redraws under 0.6·TARGET_MS: `target = min(TARGET_MAX, target·1.05)`.

τ changes only after camera-driven redraws, so a still camera never redraws. The morph's t uses the current τ, so a change of τ moves texels continuously.

### 5.12 Marks and lines (exact BSP insertion)

`DrawEffects` in mesh mode calls `Room.Line(x1,y1,z1, x2,y2,z2, r,g,b,a, thick)` in arena coordinates:

- Rings: points at `Room.FloorZ(x, y, GroundZ(x,y)) + 0.08`; 20 segments per ring.
- Columns: from FloorZ up to FloorZ + column.
- Beams: as today (GroundZ + offset).
- The target circle: as rings.

`Room.FloorZ` returns the z of the floor-grid triangle containing (x, y) that is nearest to the hint, within 1.5 yd (SlotAt's barycentric code). Otherwise it returns the hint.

Algorithm:

1. Clip at NEAR in camera space (3D lerp). Skip the segment if both ends are behind.
2. Insert iteratively with a small explicit stack of pending `(k, P1, P2)` entries, starting at the root:

```lua
local s1, s2 = Plane(k, P1), Plane(k, P2)
local c1 = s1 > LINE_EPS and 1 or (s1 < -LINE_EPS and -1 or 0)
local c2 = s2 > LINE_EPS and 1 or (s2 < -LINE_EPS and -1 or 0)
if c1 * c2 < 0 then                                -- straddles: split at the plane, both halves continue at k
    local t = s1 / (s1 - s2); local M = P1 + t * (P2 - P1)
    push(k, P1, M); push(k, M, P2)
else
    local c = (c1 ~= 0) and c1 or c2               -- lying in the plane (0,0) counts as the camera side
    local cam = sideSign[k] and 1 or -1
    if c == 0 or c == cam then                     -- after node k
        local ch = sideSign[k] and NFR[k] or NBK[k]
        if ch == 0 then PlaceAfter(k) else push(ch, P1, P2) end
    else                                           -- before node k
        local ch = sideSign[k] and NBK[k] or NFR[k]
        if ch == 0 then PlaceBefore(k) else push(ch, P1, P2) end
    end
end
```

Placement:

- `PlaceAfter(k)`: frame `frameOf[k]`, position `pos[k] + 1`, key `2·rankOf[k] + 1`.
- `PlaceBefore(k)`: with `r = rankOf[k] − 1`, the bottom line frame (position 0, key −1) if r < 0; otherwise `j = orderNode[r]`, frame `frameOf[j]`, position `pos[j] + 1`, key `2r + 1`.
- Then project both ends and record the placed segment (arena ends, screen ends, key, colour, thickness).
- Take the next Line from that frame's pool (`frame.lineUsed`). Its setters are cached: SetDrawLayer, SetThickness and SetColorTexture only on change; `SetStartPoint("BOTTOMLEFT", scene, x1, y1)` and `SetEndPoint` only when an end moved by more than 0.01; Show if hidden. Any setter call sets `linesChanged`.

`Room.EndLines()` hides the pool tail of each frame.

Lines sit under the ModelScene, so a character in front covers them. A line in front of a character is copied (§5.13.5). Labels and plates stay on top in plateFrame, unchanged.

### 5.13 Actor occlusion: copies above the single ModelScene

#### 5.13.1 Occluders (UI.lua `BuildOccluders`, using reused tables)

One record per shown unit actor, including the dead ones still shown:

- `x, y`
- `z = u.z or GroundZ(u.x, u.y)` (the same value the actor is placed at)
- `h = u.plate or u.tall or PLATE_HEIGHT[u.kind] or 2.6`
- `w = max(1.2, min(2·(u.radius or 0.6), 0.6·h))`
- `rb, top` = the radius and height of `actor:GetActiveBoundingBox()` × scale, under pcall. Keep the running maximum per actor model key, so the box never shrinks or bobs.
- `prio`: 2 for the player, 1 for everyone else.

Attached fx raise `top` to `max(top, fxZ + 1.5)`. A flying missile gets its own record: `z = fxZ − 0.6`, `h = 1.2`, `w = 1.0`.

`Room.SetOccluders(list, n)` computes the derived fields below and sets `occChanged` when the set changed, any position moved more than 0.01 yd, or any box edge moved more than 0.25 px.

#### 5.13.2 Families and planes

- **Family A**, when `hd = |(Ax − ex, Ay − ey)| ≥ G_MIN` and every prism corner has d > NEAR.
  - Normal `n = ((Ax − ex)/hd, (Ay − ey)/hd, 0)`, the horizontal direction from the camera to the actor's axis.
  - Plane through the axis: `φ(P) = (P − A)·n`.
  - The camera side is `φ < 0` (since `φ(E) = −hd < 0`).
  - This is an upright billboard through the axis, facing the camera position. render_check's truth uses the same billboard (§9.2).
- **Family B**, when the camera is nearly above the actor or a corner is behind the near plane.
  - `dMin` = the minimum camera depth over the 8 prism corners, minus 0.05.
  - `φ(P) = d(P) − dMin`. Only surfaces nearer than every part of the actor qualify; that is conservative and never over-occludes.
  - If `dMin ≤ NEAR` → family **skip**: no copies, and φ ≡ +1 (empty set).
- All families share one form: `φ·w = a·Xw + b·Yw + e·w + k`, where `w = 1/d`, `Xw = WX·w` and `Yw = WY·w`.
  - Family A: `a = nx, b = ny, e = −(nx·Ax + ny·Ay), k = 0`.
  - Family B: `a = b = 0, e = −dMin, k = 1`.
  - On a planar piece this is **affine in screen space**, so clipping by it is plain linear Sutherland–Hodgman.
- There is no plane bias and no "floor under the actor" skip. That skip broke closure; the judges confirmed it.

#### 5.13.3 Screen box

- Family A. With lateral vector `l = (−ny, nx, 0)`, `R = max(w/2, rb) + 0.3` and `T = max(h, top) + 0.3`:
  - the x range covers all 8 points `A ± R·l ± R·n` at z and z + T, plus 2 px on each side;
  - the top is the maximum y of the 4 top corners, + 2 px;
  - the **bottom is the minimum y of the axis-depth feet points `A`, `A ± R·l` at z**, with no margin. The floor in front of the feet projects below this line, so it is never copied over the feet.
- Family B: the bounding box of all 8 corners; the whole view if any corner has d ≤ NEAR.
- Clamp to `[0, W] × [0, H]`. An empty box means the actor is off screen.
- The box contains render_check's billboard (±w/2 from feet + 0.15 to the head).

#### 5.13.4 Copies (`Room.DrawCopies()`)

Run only if the room redrew, or `occChanged`, or `linesChanged`.

1. **Bins.** When stale (a redraw happened since they were built), put every leaf record into a 16 × 12 screen grid by its corner bounding box. The point arrays and temporaries stay valid until the next redraw.
2. **Slots.** Pick up to OCC_SLOTS occluders that are not skip and are on screen: the player first, then by box area. An actor keeps last frame's slot j.
3. **Per occluder X** (in slot order), using reused scratch arrays (polygon vertices carry `x, y, u, v, w, Xw, Yw`):

```
for each leaf record n in the bins under box_X (deduplicated per X):
    if the leaf's bbox does not overlap box_X -> next
    corners from R1..R4 (RK = 3 or 4): x, y = Corners(...) as emitted; u, v from the texture's sent cache
        (tx.u1..v4, UL/LL/UR/LR order); w = 1/PD, Xw = WX*w, Yw = WY*w
    if phiX*w >= 0 at every corner -> next                     -- entirely on the far side of X's plane
    tris: RK == 3 -> { (UL, LL, UR) }; RK == 4 -> { (UL, LL, UR), (LL, LR, UR) }  -- the base's GPU split (LL-UR)
    for each tri:
        poly = inside box_X ? tri : ClipRect(tri, box_X)
        poly = ClipPhi(poly, X)                                 -- keep phiX < 0
        for each frag in Restrict(poly, X):                     -- §5.13.5
            if Area(frag) >= 1 px^2 then add copy items: fan of frag -> quads (v1,vi,vi+1,vi+2) + a last triangle,
                each { key = 2*rankOf[RN[n]], pool = QPOOL[RP[n]], light = QL[RP[n]], 4 corners (x, y, u, v) }
for each placed mark segment whose screen bbox overlaps box_X:
    cut in 3D to phiX < 0 (t = phi1/(phi1 - phi2)), clip the projected part to box_X (Liang-Barsky, converting the
    screen parameter s back to 3D with t = s*dA/((1-s)*dB + s*dA)), apply Restrict on the 1D intervals,
    add line items { key = segment key, colour, thickness, screen ends }
caps: sort items by key DESCENDING (nearest first); keep the first 128 distinct keys (drop the farthest);
    stop adding items once the frame total reaches COPY_TEX_MAX (later actors get none)
positions: distinct kept keys in ASCENDING order -> q = 0..; frame = copy frame (2j + floor(q / 64)), position q % 64
emit: copy textures from per-copy-frame pools keyed by pool (cached light, layer, texcoords; 4 SetVertexOffset with the
    §4.3 formula only when a value moved by more than 0.01); copy lines from per-copy-frame line pools (cached setters)
```

4. Hide every copy texture and line that was not used this pass.

#### 5.13.5 `Restrict(poly, X)`: box-minus-box overlap rule (symmetric)

At every pixel, a copy must lie on the camera side of the plane of **every** on-screen actor whose box contains that pixel. That includes actors without a copy slot and family-B and skip actors.

- Let `others` be the occluders N ≠ X whose box overlaps poly's bbox, sorted by overlap area, largest first.
- For the first 2 of them: split each fragment into `ClipPhi(ClipRect(frag, box_N), N)` plus the parts of the fragment in the up to 4 strips of `bbox(frag) \ box_N` (left, right, and the bottom and top between N.x0 and N.x1). The parts outside box_N stay unrestricted by N.
- For any further N: apply `ClipPhi(frag, N)` to every fragment (conservative).

This replaces Design 3's whole-leaf gcut. A raider behind a pillar near the player's box stays hidden everywhere outside the player's box.

#### 5.13.6 Why this never draws background over foreground (proof sketch)

- **(a) Prefix.** For any φ with `φ(E) < 0`, the points of a ray from the eye with φ < 0 form an initial interval `[0, t*)` or `[0, ∞)`. For family A, `φ(t) = −hd + t·(dir·n)`. For family B, d increases along every ray in the frustum. An intersection of prefixes is a prefix. Dropping the lowest BSP ranks removes the far end of a prefix, because BSP rank increases toward the camera along a ray.
- **(b) Painter subset.** For any subset of surfaces drawn in BSP order, the last one drawn at a pixel is the nearest of that subset along the pixel's ray.
- **(c) Room pixels.** At pixel p, let S* be the nearest surface. If S*'s hit point is in the copy set, the copies show S*. Otherwise, by (a), no surface hit along that ray is copied, and the room below shows S*. Either way the room pixel is unchanged.
- **(d) Actors.** If actor X is the actor visible at p, it is hit at its plane crossing. Every copy at p is restricted by the half-space of every actor whose box contains p, X included, so it lies before that crossing. Copies at p are therefore always nearer than X and correctly cover it. Surfaces between a nearer actor's plane and X are not copied, so X may show through them. That is under-occlusion, which fails safe.
- **(e) Caps and drops** only remove the far end of a prefix, or whole actors' copies, so they are safe too.
- **Remaining approximation:** a real model is not a plane through its axis. Any error is bounded by the model's depth around that plane, not by its height (as the point-rank designs were).

## Appendix A: formulas

### A.1 Affine error along an edge

- Endpoints P and Q, with depths a = dP and b = dQ.
- A point at screen parameter s (0 at P, 1 at Q) is truly the 3D point at `t = s·a/((1−s)·b + s·a)`.
- An affine texture shows there the texel of 3D parameter s, which really lies at screen parameter `s' = s·b/((1−s)·a + s·b)`.
- The error `L·|s − s'| = L·s(1−s)|a−b|/((1−s)a + sb)` is largest at `s = √a/(√a+√b)`, where it equals **`L·|√a − √b|/(√a + √b)`**.
- At the true 3D midpoint the screen offset is `L·|a − b|/(2(a + b))`, which is never larger.
- Example: L = 100 px, a = 4, b = 9 gives a maximum of 20 px and 19.2 px at the midpoint.

### A.2 Morph weights (both D1 and D2 had them swapped)

- The 3D midpoint of P and Q projects to screen parameter `s = b/(a + b)`, nearer the far end.
- So the unsplit parent shows there `uv = (a·uvP + b·uvQ)/(a + b)`.
- Example: a = 1, b = 3 gives s = 0.75, so uv = 0.25·uvP + 0.75·uvQ.
- Using `a/(a+b)` as the weight of uvQ is wrong.

### A.3 Projective interpolation for copies and lines

- On a planar piece, 1/d and (any linear 3D function)/d are affine in screen coordinates. That is why polygon vertices carry `w = 1/d`, `Xw` and `Yw` and are clipped with plain linear interpolation.
- A 3D segment's screen point at 3D parameter t is `x(t) = ((1−t)·dA·xA + t·dB·xB)/((1−t)·dA + t·dB)`.
- Inverse: `t = s·dA/((1−s)·dB + s·dA)`.
